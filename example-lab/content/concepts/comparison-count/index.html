Comparison count
The number of times a sorting routine tests one key against another while sorting one input. It depends on the routine and the input's order, and not on the machine that runs it.

Why it matters here

Because it does not depend on the machine, a comparison count re-derives exactly from the committed evidence anywhere — which is why this lab measures it instead of time.

Worked example

Sorting an already-sorted list of n keys, insertion sort makes n − 1 comparisons, one per element, each confirming the element is already in place. Merge sort still splits and merges, making roughly half of n·log₂n.

The trap

A comparison count is not a running time. Moving elements, allocating buffers and cache behaviour all cost time and none of them is a comparison, so a routine can compare less and still run slower.
